## 1. Modelo de Inteligencia Artificial

### 1.1. Explicación del modelo

El modelo utilizado fue el de **regresión logística**. Es un modelo de clasificación capaz de calcular las probabilidades y clasificar diferentes categorías a través de betas, coeficientes, etc. con la ventaja de que no necesita una gran capacidad de procesamiento (más ligero).

### 1.2. Preprocesamiento

Junto con el modelo, se utilizó una técnica de procesamiento de texto llamada **vectorización TF-IDF**, la cuál en palabras simples, crea una matriz con la frecuencia e importancia de las palabras en un *corpus* (gran conjunto de textos).

### 1.3. Pipeline (tubería)

La regresión logística solo trabaja con números por eso se utiliza esta transformación a los textos, pasando de lenguaje natural a números como tal. Como resultado, tenemos un modelo simple capaz de entrenarse con un gran corpus y predecir el sentimiento de un *documento* (oración) en producción.

### 1.4. Performance (desempeño)

Luego de preparar los datos con los que se entranará el modelo (datos que se explicarán en la siguiente sección) se entrenaron **3 modelos distintos** al mismo tiempo para ver el desempeño de cada uno y **escoger el mejor modelo** (a este proceso se le llama *benchmark*). Los modelos utilizados aparte de la regresión logística fueron **Naive Bayes** y **Support Vector Machines**. En general los 3 modelos tuvieron un performance similar en todas sus métricas:

## 2. Estructura de Datos

### 2.1. El dataset de entrenamiento

Los datos utilizados para entrenar el modelo fueron unas 50k reseñas de distintas películas de la página de reseñas **IMDB**. Este conjunto de datos contiene principalmente 2 variables: la reseña como tal y el sentimiento del usuario en dicha reseña (binario; positivo y negativo). El dataset utilizado proviene de la página de **kaggle** por el usuario *Lakshmipathi N*. El enlace de donde obtener el dataset se puede encontrar en este [enlace](https://www.kaggle.com/datasets/lakshmi25npathi/imdb-dataset-of-50k-movie-reviews). Con estos datos el modelo se entrenó para poder entender los sentimientos de reseñas a través de palabras claves.

### 2.2. Alcance del idioma

No obstante, los comentarios están **únicamente en inglés** por lo que, para poder clasificar los comentarios en cualquier idioma, se utilizó la librería de **deep translator** desarrollada por Google y que traduce cualquier texto en un idioma deseado. Traducir los comentarios a **un solo idioma** permite globalizar el alcance y capacidad del proyecto.

### 2.3. Transformaciones del corpus

Anteriormente se habló del TF-IDF, pero un paso previo a que el texto pase a este proceso, al modelo y a la traducción son las **transformaciones de normalización**. El texto por sí solo no puede ser procesado por lo que antes dé se modifica el corpus con los siguientes cambios

1. **Se eliminaron todo carácter especial** y que no ayude al entendimiento del documento.  
2. Todas las letras **pasaron a ser minusculas**.
3. Se eliminaron todos los espacios.
4. Se eliminaron las **stopwords** (palabras que son conectores, preposiciones, etc.) ya que no aportan mucho a la narrativa del texto.  
5. Se aplicó una transformación de **lematización** la cuál consiste en cambiar las diferentes versiones de palabras en una sola más consistente y generalizada (esté [artículo de Médium](https://medium.com/escueladeinteligenciaartificial/procesamiento-de-lenguaje-natural-stemming-y-lemmas-f5efd90dca8) lo explica de forma detallada).

Es así como, después de todas las transformaciones de normalización el documento pasa a ser traducido, se vuelve una matriz TF-IDF y el modelo ahora sí puede analizar el sentimiento.

### 2.4. Otros datasets considerados

Otros datasets utilizados pero descartados fueron:

* **Customer Sentiment Dataset**: Este conjunto de datos posee las mismas características que el oficial. Sin embargo, posee 25k registros y el equipo decidió aprovechar el dataset con el doble de registros.
* **Bestbuy product**: Este es otro conjunto de datos considerado, más sin embargo posee algunas consideraciones no aptas para el proyecto como una clasificación por estrellas (en lugar de la binaria), la ambigüedad semántica del sentimiento neutral y la inconsistencia entre texto y clasificaciones descartaron este dataset para entrenar el modelo final.

## 7. Conclusiones

Este RFC establece las decisiones del análisis de los datos así como la modelización del sistema Sentiment API, documentando las decisiones técnicas clave, sus justificaciones y consecuencias. Sirve como referencia para todos los miembros del equipo y garantiza consistencia y transparencia en el desarrollo del proyecto.

Las decisiones aquí documentadas buscan dar a conocer:
- **Funcionamiento del modelo y benchmark** (Regresión logística vs SVM vs Naive Bayes)
- **Necesidades de limpieza, preprocesamiento y feature engineering** (Normalización, Lematización, TF-IDF)
- **Explicación y justificación del dataset** de entrenamiento y del **idioma**
- **Opciones descartadas** de otros datasets
